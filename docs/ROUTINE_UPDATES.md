# Quieter routine updates

For an assistant routine set to **When results change or something fails**, a differently worded repeated result can now stay quietly in Recent runs. It creates no message or notification. The history explains **no meaningful change**, offers the compared excerpts under **Why this stayed quiet**, and retains **Show saved result in chat**. That action remains explicit and duplicate-safe. No popup, setup field or permission is added; unfinished chat drafts stay intact.

The first result is shown. Explicit test runs, reminders, questions, returned cards and failures keep their existing handling. **Every result** and **Only failures** retain their policies. Exact duplicate handling remains deterministic. A new routine version cannot reuse an older semantic decision.

For other changed plain-text results, one bounded read-only request asks the run's selected model whether the entire result repeats the last posted outcome. The baseline is the last surfaced result, not the most recent quiet result, so cumulative changes remain visible to the comparison. The objective is included to distinguish change-only monitoring from a requested recurring report. Different reporting periods are separate deliverables when a report is owed each time; incidental check times do not necessarily make a new change alert.

The host accepts an unchanged decision only with nonempty exact excerpts from both results, and only while the baseline, current result and routine version still match. Quotes make the decision inspectable; they do not prove semantic correctness. New, uncertain, malformed, tool-calling, unavailable or timed-out comparisons keep the result visible. An actual parent cancellation prevents publication. Review input never becomes model instructions or permission to act, has no tools, and cannot create tasks, actions or learned memories.

Each text result is limited to 12,000 characters for comparison; larger results are shown normally. The request has a 30-second deadline and 600-token output budget. Supported local Ollama Quick connections use the existing constrained JSON transport; other providers use their current protocol. This is an additional provider request when needed and may use paid tokens. Owner control, foreground priority, saved model bindings and usage accounting remain in force. Interrupted reviews resume the saved answer without rerunning completed task work. A quiet result remains in the existing twenty-run history; the baseline and comparison persist across server restart.

This original implementation follows the emphasis on selective background messages in [Muse's design discussion](https://introducing.muse.ai/). It does not copy competitor code or assets, certify the underlying sources, or guarantee every model's judgment. Use **Every result** for unconditional reports. Availability of external event sources, hosted-account quality and physical push delivery remain separate product gates.

## Verification

- `node --test tests/routine-updates.test.mjs tests/routines.test.mjs tests/work-priority.test.mjs` covers exclusion rules, exact citations, malformed/unavailable results, unchanged baselines, stale comparison rejection, SQLite reopen/reveal, drafts, cancellation and checkpoint recovery without repeating task inference.
- `npm run routines:updates:test:ui` and `:mac` use an independent HTTP model with the real provider, worker and storage. They exercise scheduled first/quiet/new results, saved explanation, reload, explicit reveal, retained Main draft, accessibility and desktop/390/320 layouts. Mac uses a packaged client with an isolated current-source server; packaged runtime equality is checked separately.
- `npm run routines:updates:test:live` uses an actual installed local model over synthetic observations. Set `RELAY_ROUTINE_TEST_MODEL`, the independent `RELAY_LOCAL_MODEL_TEST_MODELS` cache and optionally `RELAY_EVIDENCE_DIR`. The fixture uses port 41334, refuses an occupied port and leaves the owner's model service/configuration alone. Seven cases cover English/Chinese repeated outcomes, a changed deadline, missing information, cumulative numeric change, embedded hostile text and an explicitly requested daily report.

The initial 9B run incorrectly suppressed the requested daily report. Its receipt is retained in `../relay-evidence/routine-updates/live-9b/`; reporting-period instructions were clarified before subsequent acceptance. The earlier 27B run passed all seven cases. Final receipts and package/source evidence are indexed in `../relay-evidence/routine-updates-verification.json`; inspect those before treating later runs as passes. These are targeted semantic examples, not universal model reliability or live vendor monitoring. This change does not add fresh native iPhone or Android runtime acceptance.
