# Memory that stays editable

Relay can learn useful, stable preferences from the owner's messages while helping with the current task. A conservative English/Chinese screen selects direct personal statements and explicit save requests; it does not extract or save facts. For eligible messages, the selected model reviews only the current owner text and that assistant's existing notes before the normal reply. A single proposal tool, or bounded JSON for chat-only models, supplies exact source quotes through the same validated `learn_memory` storage path. Detected local Ollama connections in supported Quick mode return constrained JSON proposals. Corrections name the exact existing note text; Relay resolves it to the saved identity, rejecting unknown or ambiguous text. Other connections retain numbered note slots. The focused model never chooses internal IDs or invents topic keys. Ordinary questions and task instructions skip this extra inference. Explicit “remember” requests and manually written notes also remain available in sample mode.

Open **My memories** from the assistant's name or a **Memory saved** link. Each learned note includes its source message and an exact quote. **Learn from our chats** turns automatic learning on or off; turning it off keeps existing notes and permits direct chat commands such as “Remember …” or “请记住 …”. Ordinary preference statements cannot use the manual-save tool to bypass this setting; My memories also permits manual entry in any language. Editing a note protects your wording. Forgetting removes it from the personal notes supplied to future model calls; the original conversation stays in history.

## Explicit saves with automatic learning off

“Please remember: I prefer quiet hotels” remains a direct save request when **Learn from our chats** is off, including with a chat-only model. The host permits this narrow path only for a current, direct owner request. The focused review still supplies an exact source quote and passes the normal conversation, cancellation, ordering and control-version checks. Ordinary preference statements do not trigger inference or storage while learning is off. Model tool arguments cannot enable the exception.

These explicit saves use manual-note protection, matching the prior explicit-save behavior. A future automatic correction leaves a reviewable proposal instead of silently replacing the note. Explicitly confirming an automatically learned fact gives the existing note manual protection. Repeating an already protected fact does not expose another save action or create another memory card. Each explicit batch commits its notes and control boundary together, invalidating older pending reviews. If extraction fails, no note is saved; direct entry in My memories remains available. The learning switch does not change.

Chat-only replies now receive accurate instructions about this host-managed memory behavior. They can use the supplied saved notes and acknowledge an actually saved fact. Direct forgetting also uses a host-managed selection pass; editing existing wording remains available in My memories. This does not give a chat-only model browser, computer or external-app actions.

## Direct forgetting from chat

“Forget my saved hotel preference” works through a focused selection pass for both action-enabled and chat-only model connections, even when automatic learning is off. The model sees only the current owner request and this assistant’s numbered saved notes. It selects targets; Relay checks current owner authority, note identities, unchanged contents and memory controls before deleting them together. Other assistants’ notes stay outside the selection. This explicit operation allows up to 60 seconds and 2,400 output tokens for a reasoning model to complete a selection; cancellation remains available throughout. Invalid selections, cancellations and concurrent owner edits leave notes untouched. A completed deletion also invalidates older pending learning so it cannot restore the removed note.

Simple forget commands receive a short acknowledgment generated from Relay’s recorded result, without another model call. A failed selection cannot become a false deletion claim. The existing **Memory forgotten** link opens the remaining notes; no popup or confirmation step is added. An exact “Forget all my saved memories” request needs no selection inference. Requests about all _preferences_, qualified requests and other specific subjects still need selection. Combined forget-and-do-something requests continue to the assistant with the recorded outcome; their generated prose remains model-dependent.

Detected local Ollama connections in supported Quick mode use a constrained, read-only JSON selection containing exact saved note text. Relay resolves that text against the frozen notes before applying the same ownership, cancellation and stale-edit checks. Model default and other providers retain the numbered-slot selection. Relay does not enable Quick on the owner’s behalf; supported Quick mode uses deterministic sampling for this narrow operation. The wire format follows [Ollama’s structured-output documentation](https://docs.ollama.com/capabilities/structured-outputs). Relay validates every returned selection itself; schema validity does not establish whether a model interpreted the request correctly.

Bare references such as “Forget that preference,” including narrow future-only qualifiers such as “I might change someday,” return a clarification without model inference or deletion. A trailing presentation request such as “Acknowledge in one sentence” is removed from selection input; substantive corrections and conditions remain. If selection fails or leaves the target unclear, a **My memories** link appears with the reply. It opens the saved notes directly and preserves the chat draft, so the owner can remove a note without searching Settings. Nothing opens automatically.

The deletion and a receipt containing only note IDs commit in one transaction. Resuming the same operation cannot delete a replacement note. This removes saved personal notes, not original conversation messages, files or backups. English/Chinese eligibility is conservative; My memories provides manual removal in any language. A model may fail to identify a clear match. Ambiguous or failed matches keep the notes and offer clarification or My memories. A combined save-and-forget transaction is not supported.

Actual installed inference uses `RELAY_MEMORY_TEST_MODEL` and `RELAY_LOCAL_MODEL_TEST_MODELS` with `npm run memory:forget:test:live`; `RELAY_MEMORY_TEST_REPLY_MODE=default` selects normal reasoning instead of Quick replies. Inspect both storage and answer evidence; controlled success does not establish a model’s judgment quality.

Run `npm run memory:selection:test:live` with the same installed-model environment variables for semantic selection checks independent of the chat examples: multiple subjects, preferences versus other facts, exclusions, Chinese, no match, ambiguous or conditional requests, untrusted note instructions and exact-all handling. It compares actual deleted note identities against declared expected targets, verifies remaining notes byte-for-byte and preserves another assistant’s private note. It records every failure and exits unsuccessfully if any case fails. This is an acceptance test, not a benchmark certificate for arbitrary personal data.

For recovery acceptance, run `node scripts/test-memory-forgetting-ui.mjs --failed-selection`; add `--mac` to exercise the packaged Mac shell. These controlled-model journeys deliberately return an invalid selection, verify that no deletion is claimed or performed, then remove the intended note through the reply’s link. They cover desktop and phone layouts, independent side-chat recall, retained drafts, reload, ambiguous requests and empty state. Live inference and failure injection are separate modes.

## Corrections and control

- Newer messages can update an automatically learned fact using its stable topic key, preserving the note's identity. Older messages cannot overwrite a newer source.
- A manually added or edited note is protected. A different candidate appears as **Possible update**, with the existing text remaining active. **Use update** or **Keep mine** resolves it in place; there is no automatic popup or extra chat message. A stale review cannot accept a replaced proposal.
- Owner edits, forgetting, explicit saves and learning-toggle changes invalidate in-flight extraction. Earlier messages cannot be reprocessed after those changes. A fresh future message may teach the same preference again when learning is enabled.
- Model calls receive the current notes on every round, including after a durable run resumes. Proposed changes are excluded from the active memory context.

## Boundaries

Learning requires a current user-authored message in an active run and its owning, unarchived conversation. Source IDs come from the host, not model arguments. The evidence must appear exactly in that message. Scheduled/email runs, assistant messages and skill invocations cannot supply learned personal context. At most three notes may be learned from one message, and automatic creation stops at 200 notes. Text and quotes are capped at 500 characters.

The model is instructed to select stable, useful information, avoid secrets and inferred sensitive traits, and ignore quoted or external content. Exact quoting verifies where the text appeared; it does **not** prove the model's interpretation is correct or distinguish all pasted third-party text from the owner's own words. Semantic extraction quality, adversarial interpretation and live-provider behavior still need broader evaluation. Topic keys help updates and duplicate control, but do not provide a semantic knowledge graph or comprehensive conflict detection.

The local Quick schema limits each review to three proposals, bounded text and exact prior-note choices. It uses deterministic sampling only for this narrow review; ordinary replies retain their model settings. Recognized English or Chinese personal-statement forms supply a matching note-language hint. Mixed and unknown forms keep the instruction to preserve the evidence language. This is writing guidance, not a source or authorization decision. Invalid output or an ungrounded source quote cannot create a note. The implementation follows [Ollama’s structured-output API](https://docs.ollama.com/capabilities/structured-outputs); valid JSON alone does not prove the model’s interpretation.

The focused model review has a 20-second shared deadline and a 1,200-token output limit. It uses the request's selected model and configured fallback chain, with normal usage accounting. It adds inference cost and time for eligible statements, but no new provider, background job, popup or transcript entry. Invalid output and optional review outages do not fail the owner's main task. Stop and applied follow-ups abort pending review. Durable state avoids reviewing the same message again; successful writes preserve provenance and topic identity across a restart.

The eligibility screen deliberately does not recognize every personal statement, language or phrasing. Supported direct forms include “I prefer …”, “My … preference has changed …” and “我喜欢 …”; users can always add or edit a note in My memories. Forgetting through a model tool requires a direct current-message forget command, such as “Forget …” or “请忘记 …”, so an ordinary correction cannot delete its saved topic. These command checks are conservative syntax checks, not a general natural-language authorization classifier. Exact source quoting and topic keys still do not establish semantic correctness. Small-model trials exposed missed saves, malformed IDs, unnecessary clarification questions and incorrect claims; broad model-quality reliability remains open.

Memory is shared across the owner's Main and side chats. Separate assistants retain their own personal notes; notes are shared only across chats belonging to that assistant. Notes live in the owner's existing SQLite workspace and export; no additional hosted memory service is introduced. Original messages and private agent checkpoints have their existing retention behavior. Forgetting is not a full transcript or checkpoint purge.

## Earlier conversation details

Relay retains the latest 40 messages as immediate conversational context. Before inference, its independently implemented keyword lookup can also supply up to four relevant excerpts from older messages in **this chat**, at 1,200 characters each. It requires no setting, extra model call, new popup or history entry, and works with chat-only models. This is bounded keyword retrieval, not comprehensive semantic recall or model-generated compression. A vague reference may have no matching excerpt; the assistant must not invent the missing detail.

Models with actions can use `search_conversation` with distinctive keywords, or an empty query for newest-first browsing. Results are paginated, at most eight per page. `read_conversation_message` reads a returned ID in 6,000-character pages. IDs, roles, timestamps and exact character offsets preserve the source. File references do not automatically open old attachments.

Lookup uses the current request cutoff, assistant membership and chat scope. It cannot read other Main/side/reply conversations or future queued requests. Group handoff messages can establish a valid cutoff but are not automatically retrieved as owner questions. Routine searches stop at the run timestamp. Quoted/shared sources and all retrieved history are explicitly marked untrusted context, never current instruction, action approval or new evidence for personal-memory learning. Newer corrections and the current request take precedence. Forgetting a personal note does not remove the original conversation; that existing retention distinction still applies.
