## Simplification applied

The previous Computer screen exposed a browser URL form, navigation controls, browser/terminal tabs and several separate input controls before the owner had taken control. The new entry page has a single primary start action when resting, or the desktop with **Take control** when running. Files and command activity are disclosed only when needed. The existing public browser remains reachable below the desktop. Neither opening Computer nor returning to chat creates a history message.

The desktop now has brokered web access. One owner action grants a website connection and resumes the saved request, while direct guest networking stays disabled. Connections can send forms/uploads and are not exact transaction approvals. The broker preserves HTTPS end-to-end; it does not inspect encrypted application requests. This is a functional step toward online computer work, not a claim of Muse’s full security architecture.

## Web access follow-up

The current [Grok computer documentation](https://docs.x.ai/grok-bot/computer-and-apps) describes shared persistent browser sessions and explicit owner takeover for sensitive steps. [Muse’s security architecture](https://security.muse.ai/) describes an external permission authority with request-level egress inspection, taint tracking, credential surrogates and a separate browser broker. Relay’s newly tested transport follows the separation of guest and host authority, with expiring endpoint grants; it has not implemented Muse’s request inspection, classifiers, taint tracking, surrogate credentials or payment controls. These remain open requirements, not implied protections.

## Takeover and durable continuation follow-up

[Muse describes](https://research.meta.ai/blog/security-and-safety-for-ai-agents-our-approach-with-muse) a browser broker outside the agent runtime and a paused agent during human takeover. That is stronger than merely hiding screenshots. Relay now pauses its assistant loop and queued work at takeover, invalidates pre-handoff computer plans, and keeps durable tool checkpoints for resume. Nine additional Node cases and four real-computer desktop/mobile flows cover this path.

Relay now puts agent shell commands and their detached child applications in a separate container. [Docker pause](https://docs.docker.com/reference/cli/docker/container/pause/) uses the kernel freezer, so double forks and changed sessions remain covered. The desktop browser and owner-launched applications stay outside that freezer. Shared X access and the shared workspace still prevent treating this as Muse’s trusted browser/credential boundary. Browser-induced work, protected browser writes and credential surrogates remain explicit W05 requirements; no process-name allowlist is used.

The real detached-process check exposed a one-write shutdown race in the initial implementation. [Docker’s kill path](https://raw.githubusercontent.com/moby/moby/master/daemon/kill.go) signals the init and then resumes a paused task. Relay now queues fatal signals for all workload processes from an unprivileged, mount-free helper sharing only the command PID namespace before removing the container. The same acceptance test passes with no extra writes. This is original implementation code, not code copied from Docker or a competing assistant.

## Background jobs follow-up

The current [Hermes process documentation](https://hermes-agent.nousresearch.com/docs/user-guide/features/tools/#background-process-management) distinguishes start, poll, wait, logs, input and cancellation, with retained results scoped to the owning conversation. Relay now has an independently written job supervisor and host journal for start/status/list/stop, conversation-scoped model access, bounded logs, takeover freezing and same-task continuation. A service restart reconnects to the same live guest process; a stopped/replaced guest is reported as interrupted without replay. Relay now additionally provides real PTY input, Ctrl-C/EOF, same-session input recovery and idempotent input receipts. Full terminal emulation, resize and broader execution backends remain open. The comparison informed behavior only; no Hermes supervisor code is included.

## Trusted browser runtime follow-up

A separate host Chromium runtime and authenticated owner HTTP endpoints now exercise the credential/request authority. Runtime acceptance exposed a redirect gap in the original routing harness; request-stage CDP interception now reviews every hop. Accessibility targets, known-value masking, binary request bytes, durable action receipts and cancellation through the computer-control contract are implemented. The implementation is disabled by default and now has a Computer Browser view and bounded model tools. Desktop/phone browser journeys pass local sign-in and exact reviewed submission through a real worker. The packaged Mac remote client also passes. Six actual Docker/Colima checks now compose the private browser and assistant tools with detached-command freezing, named-volume/PID/network boundaries, guest-to-host probes and a single reviewed submission. An actual iPhone Simulator also passes private sign-in, restart during exact review, submission once and explicit data clearing with real Docker takeover. Native testing exposed and corrected handback occlusion after keyboard scrolling. Complete host Chromium OS egress/resource auditing, physical-device/Android and live-account acceptance, release repackaging, and a practical bounded review policy remain required. See [the current scope and limitations](TRUSTED_BROWSER.md).

## Existing runtime startup — October 12, 2026

The installed Colima 0.10.3 CLI, [official FAQ](https://colima.run/docs/faq/), and [official start command source](https://github.com/abiosoft/colima/blob/main/cmd/start.go) establish that profiles can be selected explicitly and that automatic context activation, configuration saving and SSH configuration can be disabled. Relay now discovers only a matching existing stopped Docker profile at a local Colima socket and calls fixed `start --profile … --activate=false --save-config=false --ssh-config=false` arguments. It rechecks the selected engine before continuing its independently implemented setup/open flow. The implementation accepts no command/profile from HTTP bodies or models. Read-only discovery does not start the VM; cancellation never stops a shared runtime. This is a bounded installed-runtime convenience, not a cloud VM provisioner or proof of managed-computer parity. External deletion/reconfiguration racing the CLI is outside Relay's exclusive control.

## Direct phone keyboard — October 14, 2026

Rechecked Grok's [computer documentation](https://docs.x.ai/grok-bot/computer-and-apps), which describes taking over the shared computer for a blocked step. Relay's direct phone keyboard removes the separate text-send step within owner control. It is an original interaction using Relay's existing guest queue, not a copied remote-desktop implementation. The [W3C Input Events Level 2 working draft](https://www.w3.org/TR/input-events-2/) describes editing intentions and composition; Relay handles cancellable deletion/line-break intentions and verifies browser and native behavior rather than treating the draft as implementation proof. Buffered text remains available, and no navigation or typing status enters chat history.
