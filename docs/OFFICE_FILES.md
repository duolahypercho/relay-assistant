# Working with Office source files

Attach a Word `.docx`, Excel `.xlsx` or PowerPoint `.pptx` file as usual. Open its attachment chip to read a text preview inside the existing file dialog. Download still returns the exact original. Previewing makes no model request, adds no message and preserves your unfinished draft. Long files have a **Read more** action; errors keep the original download available.

Ask the assistant to summarize, compare or revise the file. Its `read_file` tool receives real extracted content, not ZIP/binary bytes. It reads every page using a content hash, then can use `save_artifact` to return a new downloadable Office result. The original stays unchanged. Generated results retain their existing separate preview/edit pages and immutable revisions.

| Format | Readable content                                                                                                                                                                                                                                                                                             |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| DOCX   | Paragraphs, table cells, tabs, breaks, hyperlink destinations, headers/footers, footnotes/endnotes and comment text. Tracked deletions and moved-from text are omitted; inserted text is included.                                                                                                           |
| XLSX   | Sheets in workbook order, cell addresses, shared/inline strings, numbers, booleans, errors, formula expressions and saved results. Hidden sheets are labeled. Number-format identifiers/codes and the workbook date system accompany raw numeric values. Phonetic annotations are excluded from cell values. |
| PPTX   | Slides in presentation order, text from text shapes/tables, and speaker notes. Slide-number/footer placeholders are excluded from notes. Hidden slides are labeled.                                                                                                                                          |

This is a text preview, not a full Office renderer or layout-preserving editor. Images, charts, embedded objects and complex layout are not reproduced; there is no OCR. The original download is the complete file. New results use Relay's existing document, spreadsheet and slide layouts and limits. The assistant must explain this distinction when an instruction requires preserving unsupported content, instead of silently discarding it.

Spreadsheet formulas, external connections, links, macros and embedded programs never execute during reading. Saved formula values can be stale. Numeric dates and currency are raw values plus available format metadata, not a promise that every Excel display format is rendered. Password-protected files, older `.doc`/`.xls`/`.ppt`, macro-enabled formats without a supported modern file type, damaged packages and excessive content need another readable copy. Unsupported binary attachments no longer pass through the model's generic text decoder.

## Boundaries and storage

The reader opens package parts in memory; it does not extract files onto the host or fetch external targets. Part relationships determine the main document and slide/sheet order. ZIP names, duplicates, expanded sizes and read-part CRCs are checked. XML document types are rejected. Parsing runs in up to two temporary Node Workers, each with a 128 MiB V8 old-generation limit and a ten-second timeout; this is not an operating-system memory sandbox. Cancellation stops parsing. A small bounded in-memory cache avoids reparsing each page; no extracted-text database or external service is created.

Limits are 8 MiB input, 3,000 package parts, 16 MiB per expanded part, 64 MiB declared aggregate expansion, and 16 MiB of XML parts. Each XML part permits up to 300,000 nodes and 96 levels. Extracted content is capped at 500,000 characters, with up to 100 workbook sheets, 100,000 populated cells, or 500 slides. Files beyond a limit fail clearly; an apparently complete preview is never returned for content silently cut by those limits. Model/UI pages contain at most 12,000 characters and avoid splitting surrogate pairs. Later pages require the same content hash; a changed file must reopen from the beginning.

The owner-authenticated `/api/files/:id/office` route sends `Cache-Control: no-store`. The static browser-only sample and frozen review snapshots retain their original download path; they do not pretend to have a server parser. The model's tool result labels extracted content as untrusted source material, never instructions or permission. Data remains subject to the owner's selected model connection when the assistant reads it.

## Verification

Run `node --test tests/office-files.test.mjs`, `npm run build`, and `npm run files:test:office`. Browser acceptance uses actual uploaded bytes, a controlled independent HTTP provider, production tools/worker/SQLite, readable previews and revised native exports. `npm run files:test:office-mac` exercises the packaged remote client. `npm run files:test:office-local-mac` exercises the app's real local backend and Worker/module resolution. Run `npx cap sync ios` then `npm run files:test:office-ios` for the disposable native iPhone HTTPS journey. Physical devices, Android runtime, original-layout fidelity and live-model semantic judgment are separate gates. See VERIFICATION.md for completed results and receipts.
