# Live voice chat

Relay now has a separate live-call path alongside editable dictation and saved voice memos. This original implementation follows the interaction described in the [Grok Bot messaging reference](https://docs.x.ai/grok-bot/chat-and-collaboration): start from an empty composer, talk with the assistant, and retain the conversation afterward.

## Use

Choose **Start voice chat** at the right of an empty composer. If listening or speaking is missing, Relay opens Voice settings directly. Once audio is ready, a missing chat model opens AI models instead. Setup preserves the draft and starts no microphone or call. Return to chat and choose Start voice chat again when ready, then allow microphone access. After a short pause at the end of each spoken turn, Relay transcribes it and sends it to the current chat automatically. Replies use the selected chat model and play through the configured speech service. Speak over the reply or choose **Interrupt** to stop it and take the next turn. **Mute** disables the microphone track; **End call** stops capture and playback and cancels the call's pending reply. Completed work remains saved.

A compact call bar stays below the conversation heading without a modal. Status, mute, interruption and End stay visible above the scrolling messages. Setup and recovery explanations appear only when needed; the bar identifies synthesized output as AI voice. Main and side chats display a call indicator in the sidebar. Typed text remains a saved draft during the call; sending typed messages resumes after ending it. Dictation remains separate and still inserts editable text without sending. A call summary records duration and number of spoken turns; transcripts and playable replies remain in chat. While the call is active it owns playback; its saved voice-memo controls appear after the call ends. Playing older audio pauses the call, and Keep talking pauses that audio before listening resumes. Questions and action reviews still need their normal controls. A spoken yes never executes a pending approval.

A short noise that starts detection but does not become a complete utterance can interrupt audio preparation. Relay resumes that same saved reply when the noise ends. If speaking fails, **Keep talking** retries its audio without sending another message or repeating the task. After the assistant itself fails, **Keep talking** returns to listening for a new request. Late recovery responses cannot replace a newer voice turn. These recovery paths add no new controls.

When speaking uses the Relay server's Mac voice, playback starts as PCM becomes available instead of waiting for the entire recording. This happens only after the assistant run has completed. The call queues every sample in order on its existing audio context; interrupting, ending or leaving chat stops both current and scheduled audio. A failed stream stops playback and keeps the completed text available for retry. Only a fully generated recording becomes a saved memo. Existing recordings and external speech services retain the complete WAV path.

The incremental transport is authenticated and bounded. The Mac adapter reads only its own temporary mono PCM16 file, handles its unfinished WAV header, and retains the original complete WAV bytes. It does not split the answer, request another model response, or change the selected voice. No new setting or user step is required.

Saved speech whose transcript exactly matches its assistant reply uses a compact playback row beneath that bubble. The text appears once, while play/pause, seeking, AI voice identification and download remain available. Different transcripts retain the full recording card and transcript disclosure. Playback pauses when leaving chat, including while the destination page is still loading. Returning does not resume it automatically. The player wraps its controls at enlarged text sizes instead of squeezing the seek bar.

Leaving chat also ends a live call immediately, including when the destination page's JavaScript has not loaded. The workspace page has its own Suspense boundary so the chat can commit its inactive state without waiting for that download. Capture stops, pending model work is cancelled and one call summary remains. Returning before the page finishes loading preserves the typed draft and does not restart the call. A microphone permission result arriving after navigation is stopped without creating a new call. Controlled browser, development and native acceptance receipts are indexed in `../relay-evidence/voice-navigation-verification.json` when present; these lifecycle checks do not certify physical audio or provider response speed.

The loading page itself includes the same Back to chat control as the finished page. This control is available before the destination module arrives, including in a native mobile WebView without browser navigation buttons. It returns to the current conversation and draft without adding a navigation message or reopening a call.

Select connected apps or attach files before calling to talk about them. A waveform button remains available beside the draft controls when text or attachments are present; starting a call does not send the typed text. The call bar names the selected apps and file count. These selections stay fixed for the call, are included with each spoken turn, and remain in the typed draft afterward. End the call to choose different context. Every ordinary turn rechecks current file availability and app access; a removed file or changed app stops that request instead of silently dropping its context. A whole spoken stop bypasses stale selected context so it can still stop the work. Incoming share cards still use their existing Send flow.

When a request needs several selected documents, the assistant can read up to eight independent sources in one step. This applies to typed conversations too. It combines readable attachments and fixed app documents already allowed to be read automatically. Each result keeps its identity and existing source links; a failed or changed source is reported separately. Reviewed app actions and parameterized documents keep their existing flow. Large results explicitly direct the assistant to read the source individually before claiming complete coverage. No new control or setup step is needed.

Leaving the conversation, hiding/backgrounding the page, or losing the microphone ends or pauses capture. A reload does not reopen the microphone. The server ends the call after twenty seconds without its heartbeat, on computer takeover, after thirty minutes, or on restart. Calls do not continue in a locked or backgrounded mobile app.

## Services and audio

On a Mac server, **Settings → Voice → Use Mac voice** enables speaking with the installed system voice. No speech-service account is required for that output path, and connected phones play the Mac-generated audio. Listening remains a separate connection. Preview, cancellation, Off and saved-provider switching stay inline; see [Mac system voice](SYSTEM_VOICE.md) for setup, latency, portability and verification limits.

Configure a chat model in **Settings → AI models**, then use **Settings → Voice** to set up listening and speaking. Enter a compatible audio endpoint, model ID, optional key and (for speaking) voice ID. Test a recording or preview the voice inline, then save. No server restart is needed. Existing `RELAY_TRANSCRIPTION_*` and `RELAY_SPEECH_*` environment settings remain an optional server configuration. These services can be local or compatible hosted endpoints. Transcription uses multipart audio uploads and speech requests WAV output. Entered keys are submitted to the signed-in Relay server and encrypted with its model vault key. Saved keys are never returned to the browser or included in workspace exports. Live recognition, synthesis quality and compatibility with every provider/model require separate acceptance.

The browser requests echo cancellation, noise suppression and automatic gain control. An AudioWorklet batches microphone samples; a ScriptProcessor fallback supports WebViews without worklets. Both paths evaluate samples in frames of at most 20 ms so a large audio callback cannot inflate a brief noise into a sustained utterance. A bounded energy detector keeps a short pre-roll, waits for sustained speech and approximately 900 ms of silence, then encodes mono 16 kHz PCM WAV. Each utterance is at most 45 seconds. This is a transcription → model → speech pipeline, not a provider's bidirectional realtime audio API. Latency includes all three services. Background noise and acoustic echo can still create false starts, especially on speakers; real microphones, Bluetooth, headphones and physical mobile devices remain unverified.

Input recordings are not added to the workspace or database. External transcription uses browser/request memory; local listening writes private temporary audio for the on-device recognizer and removes it after success, cancellation or failure (see LOCAL_LISTENING.md). Transcripts become normal owner messages and follow the existing memory-learning setting. AI-generated output audio is saved as an authenticated voice memo. The selected external services receive audio or text only as required by the configured pipeline; their retention is outside Relay's control. This is not a claim of automatic sensitive-audio detection.

## In-app voice setup

Listening and speaking each have one saved connection. Switch each capability between its saved connection, server configuration (when available) and Off. Off preserves the saved connection; Forget connection deletes it. Turning a server-configured service off remains effective after restart. Localhost always means the Relay server’s machine, including when connecting from a phone.

The editor retains fields after provider errors. Leaving a saved key blank retains it only for the same endpoint; changing the endpoint clears its association, and an explicit clear control removes the key on save. A revision check rejects changes from an outdated settings window. Active calls or in-flight audio requests block edits to the affected connection. Each request uses the service selected at its start.

Tests use the draft connection without saving it. A transcription test uploads the selected WAV/WebM/Ogg/M4A file (up to 8 MB), returns editable text for inspection and creates no chat message. A speech test sends a fixed greeting and returns an in-memory WAV preview; it creates no saved memo. Cancel test aborts the outbound request. Navigating away also aborts it. Preview URLs are released when edited, closed or unmounted. Provider usage charges and retention still apply.

## Reusing unchanged model context

Relative-date interpretation uses that request timestamp. The system instructions no longer change on every tool step merely because the wall clock advanced. Memory, app context and permissions are still rebuilt from current state; a changed preference or revoked permission is not hidden to preserve a cache hit. After recognition succeeds, the spoken correction redirects the same request: completed results stay available, old pending actions are skipped and the model replans using the latest words. It does not cancel and reconstruct the task from a new chat message alone. The call bar remains inline, and waiting work says “Listening before continuing.”

A short rejected utterance or muting during capture releases the listening boundary without inventing a new request. A recognition failure leaves work held while the same audio can be retried. A whole spoken “Stop” or “Stop now” uses the normal durable chat-stop control; it creates no model request and leaves the call ready for another turn. ## Instructions loaded with the work

Voice requests include detailed instructions only for tools currently exposed to the model. Loading a deferred tool also restores its corresponding file, skill, PDF or Office guidance before inference. General rules for source grounding, memory, exact action reviews and honest completion remain present. Typed-chat system instructions retain their previous full text outside local Quick mode, which now shares the compact guidance. This reduces irrelevant prompt text; it does not establish faster speech on every model.

Explicit requests recognized by the existing document/routine completion checks expose `save_artifact` or `create_routine` immediately. This only supplies the full schema; it neither executes work nor grants a permission. Quoted requests and ordinary questions keep the compact catalog. Loaded schemas and matching instructions survive durable recovery and obey current tool availability.

The routine tool now requires an explicit execution mode. `reminder` delivers the saved text; `assistant` performs scheduled work using the instructions. A missing or invalid mode creates nothing and returns a correction. The owner does not need to choose a technical mode: the model selects it from the request. This prevents an omitted field silently becoming an assistant task. It cannot prove that every model will choose the intended meaning.

## Completing discovered work

The compact directory explicitly distinguishes stored mail and calendar reads from a live account connection. A disconnected account is not evidence that stored records are empty.

Loading tool instructions does not read records or perform an action. If the model stops immediately after that discovery step, Relay withholds the draft and asks it once to use the loaded tools or request essential missing information. A second unexecuted draft reports failure. This boundary survives restart, follows the current owner message and respects cancellation. A real attempted operation clears the boundary, including when the operation returns an error. Loading optional tools alongside an actual operation does not force those optional tools to run.

Repeated discovery still has the ordinary run limit. Exhausting that limit reports failure, preserves any earlier result cards and asks for a follow-up; it does not offer a retry that would immediately hit the same limit. The check applies to voice and compact local Quick requests. It does not verify every factual statement, catch every initial tool-free answer or force a particular tool after real work. It introduces no new user control.

`tests/tool-discovery-completion.test.mjs` covers explicit and guessed discovery, one bounded continuation, withheld streaming, SQLite recovery, mixed batches, tool errors, cancellation, owner steering and exhaustion through the durable worker. `scripts/test-tool-directory-live.mjs` uses six fictional saved-data scenarios with actual local inference. It does not exercise physical speech or external accounts.
