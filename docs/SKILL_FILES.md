# Skills and supporting files

Open **More → Skills → Import skill**, paste a public GitHub skill link and choose **Load skill**, choose a `SKILL.md`/ZIP file, or choose **Paste instructions**, review the method, and choose **Add skill**. Relay suggests an unused shortcut, including when the original shortcut belongs to an archived skill. Importing creates a new method; it does not run it, schedule work, change another skill, or grant any tool access.

**New skill** and **Edit skill** now open on the Skills page, with an ordinary back button. The chat's **Save as skill** shortcut still opens a small dialog so the source reply stays available. Chat drafts remain intact. Existing slash selection, versioned runs and pinned routine methods keep their behavior.

**Share skill** opens an editable file preview. Review it, then download the exact reviewed file. On native phones the same control opens the system destination picker. The method, supported metadata and included supporting files are selected for export, excluding local IDs and provenance fields. Skills with supporting files download as a ZIP; standalone instructions remain `SKILL.md`. Expand **Supporting files** to inspect text and scripts, or remove files from the export before review. Binary assets are included byte for byte. Removing a file can break references in the method, so update its instructions as needed. Text that you put inside the method or metadata can still contain private information; the file is shown before downloading so you can remove it. Nothing is published automatically.

## Import from a GitHub link

Paste a public GitHub folder link or a link to its `SKILL.md`, then choose **Load skill**. A repository URL also works when its root contains one skill. Loading opens the existing editable review directly, including supporting files and a link to the resolved commit. Choose **Add skill** to save the copy. Source contents remain in the review until that explicit save; no script, model call, dependency installation, schedule or tool grant runs during import. The source link is shown during this review, not used as an automatic-update authority. Existing file/ZIP import stays available, and manual instructions start behind **Paste instructions** to keep the initial screen compact.

**Cancel download**, editing the link or leaving import cancels the request. Invalid links and download errors retain the link with inline guidance. Reloading an unfinished review discards it; a saved skill persists. The original chat draft is preserved. A newly added skill gets an unused shortcut without changing existing or archived methods.

Relay uses GitHub's [reference](https://docs.github.com/en/rest/git/refs), [commit](https://docs.github.com/en/rest/git/commits) and [tree](https://docs.github.com/en/rest/git/trees) APIs to resolve a branch/tag to a fixed commit and walk only the chosen folder. Slash-named branches resolve through actual reference names. Ambiguous branch/tag names require a commit permalink. Supporting files are fetched from the fixed commit on `raw.githubusercontent.com`; each byte count and Git blob hash must match the tree. A moved branch cannot mix file versions within an import. API-returned download URLs are never followed. Public HTTPS addresses are checked and DNS-pinned by the existing transport; redirects and account credentials are excluded.

The existing skill limits still apply: one root `SKILL.md`, up to 64 supporting files, 256 KiB per support file, 1 MiB combined support contents, and no links, submodules, path traversal, colliding names or nested skills. The loader bounds metadata and complete listings, permits two active loads, caps a load at 75 seconds and 85 requests, and aborts on client disconnect. Files stay in memory and are never extracted onto the server. GitHub's unauthenticated rate limit can interrupt downloads; retry later or use the existing ZIP import. Private repositories, GitHub Enterprise/other hosts, arbitrary Git operations, dependency installers, a marketplace and automatic updates remain open.

`skills:repository:test:ui`, `skills:repository:test:mac` and `skills:repository:test:ios` exercise an original GitHub-shaped HTTP fixture through the production loader, real storage and a controlled model. They check cancellation, retained drafts, versioned review, exact files, explicit save and a real imported-reference tool call. `skills:repository:test:live` requires `RELAY_SKILL_REPOSITORY_TEST_URL`; it contacts public GitHub and saves only a hash/size receipt, without retaining or installing external content. That transport check is separate from model quality and device interaction. No competitor implementation, prompt, script or image is bundled into Relay.

## Format and limits

This is an original implementation of the public [Agent Skills directory format](https://agentskills.io/specification), with bounded package import and execution through Relay’s existing private computer. `SKILL.md` has YAML frontmatter with `name` (a lowercase hyphenated shortcut, up to 64 characters) and `description` (up to 1,024), followed by instructions (up to 12,000). UTF-8 files are bounded to 64,000 bytes. BOM and CRLF input are accepted.

Optional `license`, `compatibility` and a flat string `metadata` map are retained. The author's compatibility note is included with a run so the model can identify missing prerequisites. License/author information survives edits, frozen runs and assistant-template transfer. Relay records its display title in `metadata.relay-title` for a round trip.

An experimental `allowed-tools` value is retained only as a note. It grants nothing and exports as `metadata.relay-requested-tools`, not as a tool grant. Existing app/tool policies and action reviews always apply. Aliases, anchors, custom tags, duplicate keys, unsupported fields, nested metadata and invalid UTF-8 files are rejected with an inline error. No arbitrary YAML constructors are evaluated.

A ZIP must contain exactly one `SKILL.md`, either at the root or in one folder matching its `name`. Up to 64 supporting files are retained with relative paths, including scripts, references, templates, binary assets and license files. Limits: 2 MiB ZIP, 256 KiB per supporting file, 1 MiB combined supporting contents, 130 ZIP entries and eight path segments. All files must belong to the same skill folder. Encrypted archives, links/special files, traversal, duplicate/case-colliding paths, invalid UTF-8 instructions, damaged CRCs and excessive expansion fail before import. Contents are parsed in memory and never extracted onto the server’s filesystem. Empty directories and original executable/permission bits are not retained.

The skill’s files are immutable snapshots in queued chat/routine runs, alongside its instructions. Edits affect future runs; routines keep their selected version. `read_skill` returns a small manifest, and `read_skill_file` reads requested text in 12,000-character pages. The requested version must match. Binary assets can be inspected after `computer_prepare_skill` copies the package into a unique working directory in the existing private computer. This uses exclusive, symlink-resistant guest file operations and existing operation receipts, cancellation and takeover checks. The source package remains unchanged. Scripts run with an appropriate interpreter through `computer_run`; importing/preparing a package does not run scripts, install dependencies, or grant tools. Required libraries must already exist in the computer or be set up separately. Preparation retries reuse receipts; the returned directory is a mutable working copy, not a read-only mount.

Assistant template v2 optionally carries `files` and `documentMeta`, including the pinned method inside a routine. Its existing 256 KB total limit still applies; larger packages must be shared separately as skill ZIPs. Template consumers that reject unknown fields need updating. Base64-encoded supporting files are not covered by the template’s text redaction heuristics; review them in the skill before sharing a template. Full cross-client execution compatibility, direct folder picking, private/other-host repository installation, dependency installation, a marketplace and automatic updates remain open.

## Package verification — October 12, 2026

Run `npm run skills:packages:test:ui`, `npm run skills:packages:test:mac` and `npm run skills:packages:test:ios`. The original packing-list fixture imports a ZIP, reads its reference through a real HTTP model tool call, copies every source byte into an isolated Linux computer, executes its Python helper and exports a CSV. The test checks the CSV rows and Unicode content. The model is controlled; this tests real transport, file handling and computer execution, not a live provider’s reasoning quality. Run `npm run skills:files:test:ui`, `npm run skills:files:test:mac` (after packaging), and `npm run skills:files:test:ios` (macOS/Xcode). Native acceptance creates and deletes its own Simulator and trusts its temporary test certificate only inside that device. The live model fixture is an independent local HTTP service, not a paid provider or a claim about model quality.

Evidence is stored in `../relay-evidence/skill-files-*-acceptance.json`. Browser and packaged Mac acceptance checks real file input/download bytes, reviewed editing, duplicate-safe round trips, model delivery, draft retention, light/dark accessibility and responsive overflow. The native iPhone check covers text import, inline editing, the actual destination picker and saved file bytes, model delivery and draft retention. ## Verified saves from chat

For a direct request to save a skill, the assistant now verifies that a method was actually saved for that owner request before claiming completion. A server-owned receipt binds its run, chat, assistant and exact version/content fingerprint. Old, archived, changed or unrelated methods and navigation alone do not prove saving. A completed bound specialist may return the saved method. Unsupported prose stays hidden for one automatic repair; repeated failure is explicit. A successful save survives model disconnect without an extra method or version. Saving does not execute a skill or grant permissions, and normal version checks still apply.

`tests/skill-completion.test.mjs` exercises these boundaries. `scripts/test-voice-catalog-live.mjs --typed --mac` includes a real-model deferred save and compares exact requested instructions. The verification record retains the false-completion trial that motivated the guard.

Older unfinished checkpoints retain their original completion behavior because their files or methods may predate host provenance. They do not repeat those saves just to obtain a receipt. New requests and their subsequent restarts use the verified-save contract.
